Which content pages should a reviewer open first?

A ranked, reason-coded review queue for CTR and engagement fixes, compared against a trained model on clients it never saw. A FlyRank ML internship project.

Abstract · The problem · Data · Method · Results · Limitations · Recommendations · Reproducibility · Credits

Abstract

Which of a client's pages should a content reviewer open first for a CTR or engagement fix? We analyzed 120,258 pages from 47 real clients, using features from January and February 2026 to predict an outcome measured in March. We compared a transparent rule (score a page by how much exposure it has and how far its CTR or engagement sits below the norm for its position) against a logistic regression and a random forest, and tested everything on clients the models never saw. On the pre-registered held-out clients, the model did better at the very top of the queue (precision@10: 50% vs 30% for the rule), while the rule held the wider cut (precision@50: 44% vs 32%), against a 15.9% base rate; the random forest did not generalize. The rule-vs-model comparison is not stable across splits or label definitions, so we do not claim the rule is reliably better; it is chosen for transparency. We then pre-registered a stricter test on fresh clients, using a 0.30pp cutoff chosen on the training split alone. There logistic regression clearly beat the rule (precision@50 92% vs 22%, about 5x the base rate), and the win held even when we looked only at pages a reviewer could actually act on. So if a team adopts the stricter definition, it should rank with the model; the rule stays the transparent baseline at the committed 0.1pp definition. The result is a ranked, reason-coded review queue that tells a reviewer which pages to open first, and why.

1. The problem

A content reviewer's job is triage: thousands of pages per client, limited hours, and a queue that has to be built somehow. This paper tackles one decision: which pages to open first, and for what kind of fix.

  • The decision: which high-exposure pages to review first, for a CTR fix (title, meta, snippet, intent match) or an engagement fix (on-page structure, depth, intent fulfillment).
  • Who acts on it: a content reviewer or editor. The queue only decides the order; a human does the reviewing and editing.
  • Cost of a wrong call: review time spent on pages that were never going to move, or pages that could have improved never getting looked at.

Why a score instead of a single cutoff? A blanket rule like "fix every page with below-average CTR" does not fit every page. A CTR gap that is normal for one content type can be a real problem for another, and engagement gaps depend on intent. So instead of flagging one slice, we score the whole queue. The question this paper actually tests is whether a simple, explainable rule can rank that queue as well as a trained model on clients it has never seen.

2. Data

Everything here runs on the FlyRank ML Internship warehouse (a gated Hugging Face release). Two tables matter:

  • fact_content_daily_performance: daily search and analytics per page (impressions, clicks, average position, sessions, engaged sessions).
  • dim_content: page metadata such as content type, main intent, and created/updated dates.

Time windows

  • Feature window: January 1 – February 28, 2026. Everything a model is allowed to see.
  • Outcome window: March 2026. Where the label is measured.
  • Decision moment: March 1, 2026. At that point the feature window is known and the outcome is not.

Unit of analysis: one row is one page (content_hash_id) for one client, summarized over the feature window.

What we left out, and why

  • Measurement flags (gsc_data_available, ga4_data_available): used only to filter rows, never as features.
  • trend_direction and trend_pct: they answer a different question (trend decline), not which pages to fix.
  • Pages under 100 impressions: not loaded at all.
  • Pages under 500 impressions: kept out of the queue because their CTR is mostly noise. This misses some real opportunities, but that is the stated cost of a low-noise queue.

Public safety: only pseudonymized hashes ever leave the notebook. No client names, URLs, or raw queries.

3. Method

The label: below_tier_outcome. A page counts as a "positive" when its CTR in the outcome window (March 2026) is more than 0.1 percentage points below the weighted CTR median of its position tier. The label is the observed outcome and nothing else. An earlier version of the label also required the same gap in the feature window. That was a leak: the feature-window gap is a feature, so half the label would have been knowable on decision day. That condition is gone.

Features

Everything the models see is knowable on March 1:

  • log_impressions_fw, ctr_fw, avg_pos_fw, pos_volatility_fw, engagement_rate_fw, log_sessions_fw, tier_ctr_gap
  • content_type, main_intent, position_tier

Baseline

A transparent rule that any human can check: score = has_volume * max(tier_ctr_gap, 0) * impressions_fw. It ranks pages by exposure times gap, with a floor of 500 impressions. This is the rule the playbook uses.

Models

Logistic regression and a random forest, with scaled numeric features and one-hot encoded categories, balanced class weights, and random seed 42.

Validation

Two splits on the same data. A random split (pages from the same client can land on both sides) and a client-holdout split (whole clients held out). The client holdout is the number that matters, because the queue has to rank pages for clients the model has never met.

Leakage checks, four

  1. Feature window: every feature ends before March 1.
  2. Product flags: none exist in the warehouse.
  3. Tier medians: recomputing them on training data only changed precision by almost nothing, so the effect is real but mild.
  4. Label source: the corrected label uses the March outcome only. 9,858 pages would differ under the old two-window label.

4. Results vs baseline

The number that matters is the held-out table below: whole clients held out, at a 15.9% base rate.

Method (client holdout) Precision @10 Precision @50
Rule-based baseline 30% 44%
Logistic regression 50% 32%
Random forest 10% 14%
Base rate (no model) 15.9% 15.9%

The random forest did not generalize to new clients, and its exact precision moved a few points between runs in our environment, so we report it only qualitatively.

  • Logistic regression wins the very top of the queue on the pre-registered split: precision@10 50% vs 30% for the rule.
  • The rule held the wider cut on the pre-registered split: precision@50 44% vs 32% for logistic regression.
  • Both beat the base rate by a wide margin, so the ranking carries real signal.
  • These two bullets are not stable across splits: on 3 of 4 held-out splits logistic regression matched or beat the rule's wider cut, and it dominated at stricter label definitions. We report the rule because it is transparent, not because it consistently wins (see Limitations).

At a stricter "below tier" definition, the model wins, validated on fresh clients

"Below tier" is a definition choice. We committed to 0.1pp and saw the rule hold the wider cut there, but a label-cutoff sweep (xp-06) showed the comparison flips, and the stricter end looked very different. Rather than adopt a cutoff from that descriptive sweep, we pre-registered a fair test (xp-07): a fresh client holdout the sweep never touched, a cutoff chosen on the training split only by a coverage rule (the strictest cutoff that still leaves at least 10% of pages "below tier", which was 0.30pp), and a single evaluation on those virgin clients.

Method at 0.30pp (virgin clients) Precision @10 Precision @50
Rule-based baseline 30% 22%
Logistic regression 80% 92%
Base rate (no model) 18.6% 18.6%

Pre-registered win criterion (decided before the run): logistic regression wins only if it beats the rule at both precision@10 and precision@50 and clears roughly 2x the base rate. It did: 80/92 vs 30/22, about 5x the base rate, on clients no earlier decision had touched. The win survived the same audits as the earlier experiments: precision holds to k=200 (80/92/88/85% vs the rule's 30/22/17/19%), only 6% of the model's top-50 were pages created after the decision date, and the top-50 spread across two content types and 6 of 10 clients, so this is not a brand-new-page artifact. The strongest check came last: we recomputed precision on only the pages a reviewer could actually act on, pages with at least 500 impressions and at least a month of history. There the model still separated cleanly (precision 90/90/87/88% for k=10/50/100/200, against the rule's 30/22/17/18.5%), and none of its top 200 pages were comparison articles, so the win is not hiding in a narrow niche.

  • The transparent rule is near its base-rate floor at this definition (p@50 22% vs 18.6%): scoring exposure times gap stops separating pages once "below tier" means far behind the tier median.
  • If the stricter 0.30pp definition is adopted, logistic regression is the validated model; the rule remains the transparent baseline at the committed 0.1pp definition.
  • We also ran a second fresh split at the same 0.30pp definition with stronger models (gradient boosting and blends). Every method hit 100% precision, which is too good to believe. The decisive test showed that was a client-mix quirk of that particular split, not a real edge, and nothing beat the pre-registered logistic regression. So logistic regression stays the validated model; the full record is in the experiment log.

The trap we avoided: on a random split the models look near perfect (precision@50 96% for both), because pages from the same client leak across both sides. The drop from that split to the client holdout is how much memorization was hiding.

The signal behind the rule

Weighted CTR falls steadily as pages sit lower in the results. The rule leans on that gradient by scoring exposure times gap.

5. Limitations

What this work cannot claim:

  • No causal claims. Ranking pages by opportunity does not prove that editing them lifts CTR. That would take a controlled experiment.
  • One snapshot. The queue is built at one decision moment (March 1, 2026) and does not follow pages over time.
  • Fixed calendar window. Every page shares the same feature window, but some clients started tracking later, so younger clients get less history or drop out.
  • Tier medians are portfolio-level, not per query. A page can rank for terms where low CTR is normal (comparison or branded queries) and still be a false priority.
  • The 500-impression floor is a deliberate trade-off. It keeps the queue low-noise but misses real opportunities on smaller pages.
  • The engagement arm is directional, not validated. It treats one click as roughly one engaged session, a conservative proxy for content fixes.
  • Client mix shifts the base rate. The held-out clients happened to have a lower below-tier rate (15.9% vs 57.5% on the random split), so results depend on which clients the queue is applied to.
  • Random forest precision was not stable run to run in our environment, so we report it only qualitatively.
  • We tried harder models; none beat the rule on the pre-registered split. Beyond the ones shown here, we ran an extended experiment round (gradient boosting, extra features, and a wider model zoo). None of them beat the rule on the pre-registered split under the committed 0.1pp definition, on pages that actually existed at the decision moment; the apparent wins were artifacts of ranking brand-new pages. Full record in the experiment log.
  • The result depends on how "below tier" is defined. We swept the label cutoff around the committed 0.1pp value. On the pre-registered split the rule beats logistic regression at that cutoff and looser ones, but at stricter cutoffs (0.2–0.3pp) logistic regression dominates, and beyond ~0.4pp no page in the data is below tier at all. The committed 0.1pp definition stays; the sweep is recorded in the experiment log.
  • The rule-vs-model comparison is not stable across splits. The wider-cut rule win in Section 4 is from the pre-registered split (seed 42); across three other client-holdout splits logistic regression matched or beat the rule's precision@50 (3 of 4 splits at the committed cutoff, 4 of 4 at stricter label definitions). The pre-registered confirmatory test on fresh held-out clients (xp-07) then validated the strict-cutoff logistic-regression lead: at 0.30pp the model reached precision@50 92% vs the rule's 22% (about 5x the base rate), while the rule sat near its base-rate floor. At the stricter definition the model is the recommended choice; the 0.1pp rule remains the transparent baseline.

6. Ranked recommendations

The playbook turns the validated rule into a ranked queue for a content reviewer.

Score: two arms, added together.

  • ctr_arm: exposure times the CTR gap over the tier median, only for pages with at least 500 impressions and a gap over 0.1 percentage points.
  • eng_arm: the engagement gap below eng_target (the weighted median engagement rate for the page's content type and intent), scaled by sessions, only for pages with at least 50 sessions.

Validated alternative: a pre-registered test on fresh clients (xp-07) showed that under a stricter "below tier" definition (0.30pp instead of 0.1pp) a logistic regression clearly beats the rule (precision@50 92% vs 22%, about 5x the base rate), where the rule sat near its own base-rate floor. Teams that adopt the stricter definition should rank with the model; the rule stays the transparent choice at the committed 0.1pp definition.

Queue: pages with a ctr_opportunity or an engagement_gap flag, sorted by score, highest first. Refresh-only pages are counted but kept out, because refreshing is a scheduled task that does not need editorial ranking. The queue at the decision moment holds 48,704 pages.

Try it live: explore the ranked queue interactively, sort by reason code and archetype, and inspect the per-action mix behind the queue.

Reason codes:

  • ctr_opportunity: visible page below its tier CTR. This is the validated signal.
  • engagement_gap: sessions but engagement below eng_target. Directional context.
  • refresh_decay: old or stale and still visible. Context from the paper's freshness findings.

Archetype to action

Archetype What the page looks like Action
visible_ctr_underperformer high volume, CTR below tier, page 1 or top 3 review_snippet_ctr
visible_ctr_striking high volume, CTR below tier, positions 11 to 20 improve_relevance_striking
visible_ctr_stale ctr gap and also old or stale review_snippet_and_refresh
visible_engagement_weak sessions but weak engagement review_onpage_engagement
mature_visible old or stale, no ctr gap refresh_mature_page
low_visibility everything else monitor

What is never automated: editing or publishing pages, deleting or merging pages, refreshing content without a human copy review, or using the queue as a causal claim. The queue ranks pages for a person; it does not decide on its own.

Where it stops being valid: it is decision support for one snapshot, the tier medians are portfolio level, and the engagement arm is directional. Monitoring triggers decide when the queue needs rebuilding (tier median drift, base rate shift, rolling precision).
